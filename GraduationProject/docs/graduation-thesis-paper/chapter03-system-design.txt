第3章  系统设计

3.1  引言

第2章明确了系统需求；本章在此基础上说明总体结构与核心部分的设计方案。系统采用前后端分离架构，前端负责人机交互与页面展示，服务端负责鉴权、业务编排与数据持久化，大模型、嵌入与联网检索等外部能力由服务端统一封装，以降低与具体供应商的耦合。

本章给出用户、会话、消息、知识库与研究任务等实体及其关联关系，并约定业务数据与用户信息的存储划分。设计重点包括四部分：用户认证与会话管理；普通对话及 ReAct 工具循环（主路径以简单问答与深度研究分流为主）；知识库检索增强对话；深度研究各阶段编排及 trace、产物展示。同时对异常返回、并发访问和界面交互等非功能要求作出约定。全章配合架构图、模块图、实体类图、时序图与活动图展开，为第4章实现与第5章测试提供依据。

3.2  系统架构

本系统为 B/S 与前后端分离：前端采用 React+Vite 单页应用，经 JSON 调用 Express（Node.js）后端；会话与消息、知识库、研究任务等持久化于 SQLite（默认 data/app.db），用户账户等当前存于 data/users.json，逻辑上仍归为用户域。大模型、嵌入与联网检索由环境变量配置的外部服务提供，经封装客户端调用，与业务进程解耦。总体结构见图3-1。

前端采用 React 组织页面与组件，负责路由、会话与聊天等交互状态；Vite 负责开发与打包。用户在浏览器中操作界面，由前端将登录、会话、知识库、研究等请求以 HTTP（开发环境可为本地 HTTP）与 JSON 载荷发送至服务端接口。

服务端基于 Express 注册路由与中间件：除注册、登录、邮箱验证等公开接口外，受保护接口在统一鉴权逻辑中解析 Bearer Token，未携带或无效时返回 401；通过后进入各业务路由处理函数，调用聊天仓储、知识库仓储、研究存储及大模型客户端等模块完成业务并返回 JSON。

数据方面，会话、消息、知识库分块与研究任务等结构化数据存放在 SQLite（app.db）；用户账户、验证与验证码等当前实现为本地 JSON 文件（如 users.json），与库表在部署上分离但在领域上仍视为用户数据。大模型推理、向量嵌入与联网检索由外部服务承担，服务端仅保存调用所需配置与业务侧产物，不在库内持久化模型参数。

前后端职责清晰、接口以 REST 为主，便于替换模型供应商、扩展新路由或独立演进前端展示，有利于后期维护与功能扩展。

3.3  系统功能模块

结合第2章用例，本系统将功能划分为七个模块：用户认证与账户、多会话聊天、ReAct 工具编排、知识库管理、检索增强对话、深度研究任务、研究过程与产物展示。各模块在服务端通过路由与仓储类协作，前端以聊天主界面、知识库页及设置面板提供入口。

如图3-2，模块按「先登录与会话、再在会话中扩展能力」组织，虚线表示常见触发关系。用户认证与账户模块负责注册、邮箱验证、密码与验证码登录、找回密码及令牌鉴权，是多会话与业务数据的安全前提。多会话聊天模块构成系统核心：完成注册验证与登录后，用户可创建、切换与删除多个会话，发送消息并接收助手回复，历史消息持久化保存；系统在用户发出首条有效消息后自动生成或更新会话标题，便于在侧栏识别主题。

知识库管理模块支持集合的创建与命名、文本分块与嵌入入库、分块编辑与批量删除，并可在会话维度绑定一个或多个集合，为结合自有资料问答提供基础。检索增强对话建立在发送消息流程之上：若会话已绑定知识库，则将用户问题嵌入为查询向量，对各集合检索后按相似度合并与最低分阈值过滤，再把命中片段格式化后并入提示词；未绑定或未达阈值时按普通对话处理。

ReAct 工具编排模块在需要确定性能力时由模型发起工具调用，服务端经注册表执行计算器、时间等内置工具并回填观察结果，可多轮循环直至终稿；其与主聊天路径解耦，主路径以简单问答与深度研究自动分流为主。深度研究任务模块面向需查证、对比或综述类长问题，由规划子问题、联网与知识库检索、网页抓取、证据提炼、分节写作、质量审查等阶段组成流水线，强调先证据后结论。研究过程与产物展示模块供前端轮询任务状态，渲染 Markdown 报告并展示 Trace 或管线节点，使用户对照过程理解报告来源。本系统不设独立管理端。

3.4  系统实体类及描述

3.4.1  系统实体类设计

从领域模型角度，系统核心实体包括：用户（User）、聊天会话（ChatSession）、聊天消息（ChatMessage）、知识库集合（RagCollection）、知识库文本分块（RagChunk）、研究任务（ResearchTask）。建模时以第2章用例与第3.3节功能模块为参照，实体边界与业务对象一一对应，便于映射为 SQLite 表或 users.json 中的用户条目，减少概念层与实现层的歧义。

在关联关系上，用户作为访问主体，与会话、知识库集合、研究任务均为一对多关系，体现按用户隔离数据的权限语义。聊天会话与聊天消息为组合关系，消息从属于会话，删除会话时级联删除其下消息。知识库集合与文本分块亦为组合关系，分块依附集合存储，删除集合时同步清理分块。研究任务归属用户，通过任务主键创建，再与会话中助手消息的元数据建立弱关联，便于在对话流中回溯某条长回复对应的研究生成过程，又不必把任务生命周期与会话生命周期完全绑定。

实体类图（图3-3）列出各类主要属性；除 User 存于 users.json 外，其余实体主要对应 chat_sessions、chat_messages、rag_collections、rag_chunks、research_tasks 等表，具体字段在 3.5 节说明。

3.4.2  关键实体类解释

用户（User）：系统访问主体，保存登录凭据、邮箱验证状态、密码重置与登录验证码等字段；登录成功后由服务端签发令牌供后续请求携带。

聊天会话（ChatSession）：用户在会话维度组织多轮对话，保存标题、创建与更新时间，以及本会话绑定的知识库集合标识列表（JSON 数组形式持久化）。

聊天消息（ChatMessage）：隶属于会话，记录角色（用户或助手等）、正文、时间戳及可选元数据（如关联的研究任务标识），用于前端渲染与上下文组装。

知识库集合（RagCollection）与分块（RagChunk）：集合描述知识库名称及所用嵌入模型标识；分块存储被切分后的文本与对应向量（以 JSON 形式存储于 SQLite 字段中，便于实现阶段简化序列化）。

研究任务（ResearchTask）：描述一次深度研究运行的主题、状态、错误信息、结构化产物（如规划、笔记、报告等 JSON 对象）及轨迹数组，供轮询接口与前端展示使用。

3.5  数据结构设计

业务库采用 SQLite，库文件路径可由环境变量配置，默认位于服务端 data 目录。以下为与实现一致的主要表结构说明；字段类型以 SQLite 类型为主，「接受空值」中 YES 表示允许 NULL。

表3-1  聊天会话表（chat_sessions）

聊天会话表对应实体 ChatSession，按用户隔离存储各独立对话。id 为会话主键，title 用于侧栏展示并可由首条消息摘要更新；rag_collection_ids_json 记录绑定的知识库 id 列表；时间字段记录创建与最近更新时间。删除会话时级联删除其下消息。

属性	含义	类型长度	接受空值	默认值
id	会话主键	TEXT	NO	无
username	所属用户名	TEXT	NO	无
title	会话标题	TEXT	NO	无
rag_collection_ids_json	绑定知识库 id 列表	TEXT	NO	[]
create_time	会话创建时间	INTEGER	NO	无
update_time	会话最近更新时间	INTEGER	NO	无

表3-2  聊天消息表（chat_messages）

聊天消息表对应实体 ChatMessage，按会话存储用户与助手的各条记录。session_id 关联会话表主键，删除会话时级联删除；role 区分 user、assistant 等角色，content 为消息正文，ts 为时间戳，meta_json 可存放研究任务 id 等扩展信息。

属性	含义	类型长度	接受空值	默认值
id	消息主键	INTEGER	NO	无
session_id	所属会话	TEXT	NO	无
role	角色	TEXT	NO	无
content	消息正文	TEXT	NO	无
ts	时间戳	INTEGER	NO	无
meta_json	扩展元数据	TEXT	YES	无

表3-3  知识库集合表（rag_collections）

知识库集合表对应实体 RagCollection，按用户隔离存储各知识库。id 为集合主键，name 为展示名称，embedding_model 记录入库与检索所用嵌入模型，created_at 为创建时间；其下分块见表3-4。

属性	含义	类型长度	接受空值	默认值
id	集合主键	TEXT	NO	无
username	所属用户名	TEXT	NO	无
name	名称	TEXT	NO	无
embedding_model	嵌入模型标识	TEXT	NO	无
created_at	创建时间	INTEGER	NO	无

表3-4  知识库分块表（rag_chunks）

知识库分块表对应实体 RagChunk，存储集合内切分后的文本与向量。collection_id 关联集合表主键，删除集合时级联删除；chunk_index 表示集合内顺序，embedding_json 以 JSON 保存嵌入向量，供检索时计算相似度。

属性	含义	类型长度	接受空值	默认值
id	分块主键	INTEGER	NO	无
collection_id	所属集合	TEXT	NO	无
chunk_index	分块序号	INTEGER	NO	无
content	分块文本	TEXT	NO	无
embedding_json	向量序列化	TEXT	NO	无

表3-5  研究任务表（research_tasks）

研究任务表对应实体 ResearchTask，记录一次深度研究运行。核心字段包括：id 标识任务，topic 为研究主题，status 表示 planning、collecting、done 等阶段状态；artifacts_json 存放规划、报告等产物，trace_json 存放各智能体动作与观察，供轮询与过程回放。另含 username 归属、error 失败说明及 created_at、updated_at 时间戳等辅助字段。

属性	含义	类型长度	接受空值	默认值
id	任务主键	TEXT	NO	无
username	所属用户名	TEXT	NO	无
topic	研究主题	TEXT	NO	无
status	任务状态	TEXT	NO	无
artifacts_json	产物字典	TEXT	NO	无
trace_json	轨迹数组	TEXT	NO	无

索引设计：在 chat_sessions 上建立 (username, updated_at DESC) 索引以加速会话列表查询；在 chat_messages 上建立 (session_id, id) 索引以加速按会话拉取消息顺序；在 rag_chunks 上建立 (collection_id, chunk_index) 索引以支持分块遍历与检索实现；在 research_tasks 上建立 (username, updated_at DESC) 索引以支持任务列表与清理策略。

用户数据文件：当前实现将注册用户条目存放于 data/users.json 的根对象 users 下，键为用户名，值为包含密码、邮箱、验证令牌与过期时间、登录一次性验证码等字段的对象。论文中可将其视为「用户逻辑表」，若后续改为关系库存储，可保持字段语义不变迁移至 user 物理表。

3.6  系统功能设计及描述

3.6.1  用户认证与会话管理功能

用户认证与会话管理保证访问主体与会话上下文可校验。注册需填写用户名、密码与邮箱，并完成 6 位验证码验证，未验证不得进入主功能，验证码可重发。登录支持密码或邮箱验证码两种方式，忘记密码可通过邮件令牌重置。登录成功后签发 Bearer 令牌；除公开接口外，受保护接口请求前由鉴权中间件校验并解析用户名，失败返回 401，前端可凭令牌恢复登录态。会话管理包括新建、列表、修改标题、删除及拉取历史消息，列表按最近更新时间排序，并维护会话级知识库绑定列表，供发送消息时触发检索增强。

3.6.2  多会话智能对话与 ReAct 工具编排功能

多会话智能对话以「发送消息」接口为统一入口，接收会话标识与用户问题，校验归属后读取历史消息组装为多轮上下文。主路径上，系统先判断是否走深度研究：若不进入，则在可选知识库检索后由大模型直接生成回复并持久化到会话；若进入，则转交研究管线异步产出报告。ReAct 工具编排作为可扩展子系统设计：编排器循环调用大模型，解析其输出的工具请求 JSON，交由工具注册表执行并将观察写回消息列表，直至模型输出最终答复或无工具请求为止，与主路径解耦，便于后续接入工具增强对话。

participant "Express\n/chat API" as API
participant "编排器\n(ReAct)" as ORC
participant "工具注册表" as TR
participant "大语言模型" as LLM

U -> FE : 输入消息并发送
FE -> API : POST 消息（带令牌）
API -> ORC : 组装上下文并迭代
loop 直至无工具或达上限
  ORC -> LLM : chat(messages)
  LLM --> ORC : 结构化输出\n(tool_requests / final)
  alt 存在工具请求
    ORC -> TR : 执行工具
    TR --> ORC : observation
  else 无工具
    ORC --> API : 最终答复文本
  end
end
API -> API : 持久化助手消息
API --> FE : 返回消息列表
FE --> U : 展示回复
@enduml

3.6.3  知识库管理与 RAG 增强对话功能

知识库侧提供集合增删、分块写入与更新、批量删除等接口；嵌入由独立模块调用外部嵌入 API 生成向量并写入 embedding_json。对话侧在用户绑定集合后，将用户问题嵌入为查询向量，对各集合分别检索后按相似度合并截断，将片段格式化写入系统提示或附加消息，再调用大模型生成回答；可配置最低相似度阈值，低于阈值时整轮不注入片段以避免噪声。

3.6.4  深度研究（规划—检索/抓取—证据提炼—写作—评审）功能

深度研究任务由独立存储记录状态与产物；运行管线在服务端异步或同步推进（实现上可与 HTTP 请求生命周期绑定），阶段一般包括：规划子问题、联网检索与网页文本获取、阅读器抽取证据要点、写作器生成章节化报告、批评者进行基础检查与可选重写、全局润色（若启用）。各阶段向 trace 数组追加事件，向 artifacts 字典写入命名产物，供前端轮询展示。

3.7  系统非功能性设计及描述

3.7.1  LLM 与外部接口错误处理与重试

对大模型聊天、嵌入及外部检索等调用设置超时与重试策略；对模型输出 JSON 解析失败时进行有限次重试或降级为纯文本段落，避免整条研究任务因单次解析失败而不可用。HTTP 层统一返回结构化错误码与中文提示信息，前端对 401、409 等状态做分支提示。

3.7.2  并发与资源控制

对同一会话并发的深度研究请求在服务端以映射表防重入，避免同一用户界面重复提交导致多任务写乱；研究任务数量可按用户维度设置上限并淘汰最早任务。消息表对单会话消息条数可截断保留最近若干条，以控制上下文规模与存储膨胀。

3.7.3  用户界面与交互设计

聊天区采用清晰的消息气泡与时间顺序；代码与列表类内容可结合 Markdown 渲染；知识库管理页提供集合与分块列表及操作按钮；深度研究页突出任务状态、耗时预期与 trace 可读性。具体配色与布局以实现为准。
